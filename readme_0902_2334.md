> `readme_3.md`가 "기획안"이었다면, 이 문서는 **2026-09-01 기준 실제로 코드에 구현되어 있는 기능**을
> 화면/기능/데이터 단위로 정리한 스냅샷입니다. 다른 탭에서 질문·꼬리질문 데이터를 작성하실 때

> 가이드"(Manus 작성) 대비 지금 구현이 어디까지 와 있는지도 정리했습니다 (§9).

## 2. 인증 — 공유 비밀번호 + 익명 로그인

- 이메일을 전혀 사용하지 않습니다 (회원가입 확인 메일, 매직 링크 전부 없음).
- `app/login/page.tsx`에서 클라이언트 코드가 입력값을 고정 문자열(`SHARED_PASSWORD = 'kmove13'`)과
  비교합니다. 일치하면 `supabase.auth.signInAnonymously()`를 호출해 Supabase 익명 세션을 발급받습니다.
- Supabase 프로젝트에서 **Authentication → Anonymous Sign-Ins**가 켜져 있어야 동작합니다.
- 로그아웃: 마이페이지의 `LogoutButton` → `supabase.auth.signOut()`.
- 이 비밀번호는 클라이언트 코드에 그대로 있는 "가벼운 문지기"이며, 실제 계정 인증이 아닙니다
  (5~10명 규모 비공개 데모 용도).

## 3. 화면별 기능

### 3-1. 홈 (`/`)
- 기울어진 호버 카드(`HeroCard`)에 "JP · 日本語面接練習プログラム" 타이틀.
- 브라우저 STT/TTS 지원 여부를 실시간으로 검사해 배지로 표시 (`SupportBanner`).
- 로그인 여부에 따라 "비밀번호 입력하고 시작하기" 또는 "레벨 체크 시작 / 바로 면접 시작" 버튼.
- 배경에 카타카나 매트릭스 애니메이션(`MatrixBackground`), 콘텐츠는 macOS Safari 스타일 창
  (`MacWindow`)에 담겨 있음.

### 3-2. 레벨 체크 (`/level-check`)
로그인 후 진입. 4단계 진행:
1. **자가 신고**: JLPT 수준(N1~N5/모름), 경어 자신감, 장음 자신감을 세그먼트 버튼(`PillRadio`)으로 선택.
2. **장음 체크**: 장음 최소 대립쌍 단어(예: おばあさん/おばさん)를 듣고 따라 말하면, 인식된 텍스트가
   "짧게 발음했을 때의 오인식 형태"와 일치하는지 비교해 장음 위험 플래그를 계산.
3. **경어 문장 체크**: 정해진 경어 문장을 따라 말하면, 문자 단위 유사도(근사치)와 정중체 비율을 계산.
4. **결과**: 위 신호를 종합해 추천 난이도(N1~N5)와 경어 모드(강제/자율/보통체 허용)를 제시하고,
   `diagnostic_results`에 기록 + `user_settings`에 반영 후 `/interview`로 이동.
- 모든 계산은 문자열 비교 기반 근사치이며, 화면에 "추정치"로 명시되어 있습니다.
- ⚠️ 참고: 질문 은행 자체는 더 이상 JLPT로 필터링하지 않습니다(§4 참고). 이 레벨 체크의 JLPT 값은
  주로 `keigo_mode`(경어 강제/자율/허용) 추천에만 쓰입니다 — 실제 면접관은 지원자 수준과 무관하게
  항상 경어로 질문하기 때문에, 질문 난이도 자체를 나눌 필요가 없다고 판단했습니다.

### 3-3. 면접 모드 선택 (`/interview`)
- 4가지 모드: 연습 / 실전 / 기술 면접 / 역질문.
- 각 모드 카드는 macOS Safari 미니 창처럼 트래픽 라이트 타이틀바가 달린 버튼(`.mode-card`)입니다.
- 모드를 클릭하면 Supabase `sessions` 테이블에 새 세션 행을 만들고 `/interview/run/[sessionId]`로 이동.

### 3-4. 면접 진행 (`/interview/run/[sessionId]`) — Zoom형 면접실 (전면 리팩터링 완료)

`zoom_style_frontend_implementation_guide.md`(Manus 작성)를 기준으로 이 화면 전체를 다시 만들었습니다.
`app/interview/run/[sessionId]/page.tsx`는 이제 `sessionId`/`mode`만 읽어 `InterviewRoom`에 넘기는
얇은 로더이고, 실제 로직은 전부 `features/interview/` 아래로 분리되어 있습니다.

**폴더 구조**
```
features/interview/
  types.ts                    InterviewPhase / InterviewEvent 타입
  constants.ts                모드→카테고리 매핑, 상태별 안내 문구
  hooks/
    useInterviewMachine.ts    면접 진행의 중심 컨트롤러 (질문 큐, 답변 확정, 저장, 꼬리질문 판단)
    useMediaDevices.ts        마이크/카메라 스트림 관리 (카메라는 버튼 누를 때만 요청)
    useAudioLevel.ts          AnalyserNode 기반 음량 레벨 (평가용 아님, 시각 피드백 전용)
    useSpeechRecognition.ts   phase==="listening"일 때만 켜지는 STT (의도치 않은 재시작 방지)
    useSpeechSynthesis.ts     질문 낭독 TTS + onStart/onEnd → 상태 전이 연동
    useSessionTimer.ts        질문별 경과 시간 타이머
  lib/
    evaluateAnswer.ts         lib/feedback.ts 재노출
    followUpEngine.ts         lib/followUp.ts + lib/questionBank.ts 조합
    choonMatcher.ts           장음 오인식 비교 유틸(레벨체크와 공유)
    transcriptNormalizer.ts   승인된 STT 보정 사전을 답변에 자동 적용
  components/
    PreflightDialog.tsx       입장 전 장치/개인정보 안내 + 마이크 테스트
    RoomHeader.tsx            48px 상단바 (나가기·모드·레벨·경어모드·타이머·연결상태)
    InterviewStage.tsx        면접관 아바타·질문·자막·다시듣기
    SelfPreview.tsx           셀프 카메라 또는 파형/이니셜 카드 (스테이지 안에 도킹)
    TranscriptPanel.tsx       현재 답변 초안 편집 영역
    CoachingPanel.tsx         STAR/PREP 체크리스트 + 규칙 기반 신호(실시간 계산)
    RoomControls.tsx          76px 하단 고정 컨트롤 바
    InterviewRoom.tsx         위 조각들을 조립하는 화면 본체
```

**면접 상태 머신**
가이드가 제안한 `InterviewPhase`(`preflight → questionReady → interviewerSpeaking → listening →
answerReview → saving → completed`, 그리고 `fallbackText`)를 채택했습니다. TTS 재생 중에는 마이크를
켤 수 없고, "답변 완료"를 누르면 곧바로 다음 질문으로 넘어가지 않고 `answerReview`(전사 편집) 단계를
반드시 거친 뒤에만 저장·다음 질문 진행이 가능합니다. `followUpReady`는 별도 대기 화면 없이 저장 직후
즉시 다음 질문(꼬리질문 또는 다음 문항)으로 전환되도록 단순화했습니다(§9 참고).

**레이아웃 (데스크톱 3영역 + 고정 컨트롤)**
- 상단 48px `RoomHeader`, 하단 76px `RoomControls` 고정, 그 사이를 스테이지(가변폭)와 352px 보조
  패널이 채웁니다. 1280px 이상에서 패널이 그리드 컬럼으로 상시 표시되고, 768~1279px에서는 80% 폭
  드로어로, 767px 이하에서는 하단 시트로 전환됩니다(가이드 §2 표 그대로 CSS 미디어쿼리로 구현).
- 셀프 카메라/파형 미리보기는 스테이지 안에 도킹되며 크기도 같은 표를 따릅니다
  (240×135 / 200×112 / 112×150).
- 사이트 공통 상단바(macOS Safari 테마)는 이 경로(`/interview/run/*`)에서만 자동으로 숨겨집니다
  (`components/SiteChrome.tsx`가 경로를 감지) — 가이드가 말한 "집중 모드".

**프리플라이트**
룸에 들어가자마자 권한 창을 띄우지 않고, 먼저 카메라 미저장/STT 외부 처리 가능성/텍스트 모드 안내를
보여준 뒤 "마이크 테스트 시작"을 눌러야 실제로 권한을 요청합니다. 마이크가 안 되면 "텍스트 모드로
계속하기"로 바로 진입할 수 있습니다.

**답변 입력 · 꼬리질문 · 피드백**
- 질문은 로컬 `data/questions.json`에서 카테고리별로 불러와 매 세션 셔플, 실전 모드 첫 질문은
  `REAL_MODE_INTRO_QUESTION`(코드 고정) — 이전과 동일합니다.
- 답변 확정 시 `transcriptNormalizer`가 이미 승인된 개인 STT 보정 사전을 자동 적용한 뒤,
  `evaluateAnswer()`(규칙 기반 피드백)와 `followUpEngine`(꼬리질문 판단)을 거쳐 그 결과만
  `session_answers`에 저장됩니다 — 중간 인식 결과나 `MediaStream` 자체는 저장되지 않습니다.
- STAR/PREP 체크리스트는 보조 패널에서 답변을 입력하는 동안 실시간으로 갱신됩니다.

**화상/음성 녹화**
카메라 on/off, 화상 녹화, 음성 녹음은 `RoomControls` 하단 바에 있으며, 이전과 동일하게 **로컬 저장
전용**(서버 업로드 없음)입니다. 카메라가 꺼져 있으면 화상 녹화 버튼이 비활성화됩니다.

### 3-5. 세션 리포트 (`/interview/result/[sessionId]`)
- 답변 수 / 평균 답변 시간 / 필러 총합 / 평균 정중체 비율(추정치)을 통계 카드로 표시.
- 질문 텍스트는 Supabase 조인이 아니라 `lib/questionBank.ts`의 `getQuestionById()`로 로컬 데이터에서
  가져옵니다.
- Markdown 다운로드 버튼(`MarkdownExportButton`)으로 세션 전체를 `.md` 파일로 내보낼 수 있습니다.
- macOS Safari 스타일 창(`MacWindow`)에 담겨 있고, 결과 화면이라 매트릭스 배경도 함께 보입니다.

### 3-6. 마이페이지 (`/dashboard`)
- 지난 세션 목록(날짜/모드/답변 수, 클릭 시 리포트로 이동).
- 내 STT 보정 사전 목록 (`user_custom_terms`).
- 로그아웃 버튼.
- 페이지 진입 시, 보관기한이 지난 음성 로그(`audio_expires_at` 지난 행)를 클라이언트 접속 시점에
  자동 정리합니다(Supabase 무료 티어에 `pg_cron` 대신 채택한 방식). 다만 현재는 화상/음성이 서버에
  업로드되지 않으므로 이 컬럼은 사실상 비어 있습니다(§8 참고).

## 4. 로컬 데이터 파일 (git으로 관리, Supabase 아님)

### 4-1. `data/questions.json` — 질문 원본
```json
{
  "questions": [
    {
      "id": "team_project",
      "category": "technical",
      "expectedDurationSec": 90,
      "textJa": "チームで取り組んだプロジェクトについて教えてください。",
      "tags": ["team_project"]
    }
  ]
}
```
- `id`: 영문 slug, 다른 질문과 겹치면 안 됨. `follow_ups.txt`에서 이 id로 참조.
- `category`: `personality | technical | culture_fit | reverse`
- `expectedDurationSec`: 권장 답변 시간(초), 타이머/짧은 답변 판정 기준.
- `textJa`: 일본어 질문만 있습니다 (JLPT 난이도 태그, 한국어 번역 없음 — §3-2 참고).
- 현재 14개 질문(메인 10개 + 꼬리질문 대상 4개)이 예시로 들어 있습니다.

### 4-2. `public/data/follow_ups.txt` — 꼬리질문 규칙 (일반 텍스트)
```
# 형식: 원래질문id | 감지할단어1,감지할단어2,... | 다음질문id | 우선순위(선택)
strength | チーム,協力 | role | 1
team_project | チーム,プロジェクト,担当 | role_detail | 1
team_project | Python,SQL,機械学習,データ | tech_reason | 2
problem_solving | エラー,失敗,課題 | how_solved | 1
```
- `#`으로 시작하는 줄과 빈 줄은 무시.
- `public/` 아래에 있어 브라우저가 `fetch('/data/follow_ups.txt')`로 직접 읽습니다 — 다른 곳을
  안 건드리고 이 파일만 고쳐도 꼬리질문 규칙을 바로 추가/수정할 수 있습니다.
- 파싱/매칭 로직: `lib/questionBank.ts`(읽기·파싱) → `lib/followUp.ts`(매칭).

**다른 탭에서 예상질문·꼬리질문을 작성하실 때는 이 두 파일(`data/questions.json`,
`public/data/follow_ups.txt`)만 편집하시면 됩니다.** 편집 후 GitHub Desktop으로 커밋/푸시하면
Vercel이 자동 재배포합니다. Supabase SQL을 다시 실행할 필요는 없습니다.

## 5. Supabase에 실제로 저장되는 것 (개인별 기록만)

| 테이블 | 용도 |
|---|---|
| `sessions` | 면접 세션 1건 (사용자, 모드, 시작 시각) |
| `session_answers` | 질문/꼬리질문별 답변 텍스트, 시간, 피드백 결과(JSON), STT 원문/수정본 |
| `user_settings` | 레벨 체크 결과, 경어 모드, 기본 설정 |
| `diagnostic_results` | 레벨 체크 진단 이력 |
| `user_custom_terms` | 사용자별 STT 오인식 보정 사전 |

`questions` / `follow_up_rules` 테이블은 더 이상 사용하지 않습니다(§4 참고). 기존에 구버전으로
만들어 둔 프로젝트는 `supabase/migrate_local_questions.sql`을 1회 실행해 정리합니다.

  무작위 풀에도 남아있어서 우연히 같이 뽑히면 자기소개를 사실상 두 번 묻는 상황이 생길 수

## 17. 2026-09-02 (8) TTS 목소리 불일치 버그 수정 + 피치 조절 + 이력서 키워드 준비 기능

## 18. 2026-09-02 (9) 세션 리포트 "평균 정중체 비율"·"종합 점수" 개편 — 진짜 버그 발견

자세한 내용은 `log/2026-09-02_작업로그.txt`의 "[15차 작업]"에 있습니다.

- **진짜 버그 발견**: 정중체/반말체를 판정하는 정규식이 사전형 어미(です/ます/だ/である)만
  잡고 있어서, 실제 답변에서 가장 흔한 ます형 활용(〜ました/〜ません/〜でした)이나 사전형
  동사·형용사 반말체(〜する/〜した/〜ない/〜い 등)를 거의 못 잡고 있었습니다. 그 결과
  대부분의 문장이 판정 대상에서 빠져서 점수가 실제보다 낙관적으로 나오고 있었습니다.
  정규식을 확장해 16개 대표 문장으로 검증했습니다.
- **"평균 정중체 비율" 계산 방식 개선**: 질문별 비율을 단순 평균하던 것을, 세션의 모든
  문장을 한 번에 모아(pool) 계산하도록 바꿔 통계적으로 더 정확해졌고, "판정 가능한
  N문장 중 정중체 M문장"처럼 근거도 함께 보여줍니다.
- **"종합 점수" 재정의**: 기존엔 말투 정확도 하나만 반영해 "종합"이라는 이름과 안
  맞았는데, 이미 화면에 있는 필러 비율을 30% 가중치로 더해 "말투 정확도 70% + 필러
  적음 정도 30%"로 재정의했습니다.
- **프런트 UI 개편**: 두 점수를 일반 stat-card보다 크고 눈에 띄는 색상 코드
  카드(80점 이상 초록/50점 이상 노랑/미만 빨강)로 분리하고, 항상 점수의 근거(문장 수,
  구성 비율)를 함께 보여줘서 블랙박스처럼 안 느껴지게 했습니다. "꼬리 질문" 배지도
  색으로 구분했습니다.

**참고**: 판정 정규식이 훨씬 많은 문장을 잡게 되면서, 같은 답변이라도 이전보다 점수가
낮게 나올 수 있습니다 — 회귀가 아니라 이전 계산이 지나치게 관대했던 것을 바로잡은
것입니다. 종합 점수 가중치(70:30)는 제 판단으로 정했고, 조정하고 싶으시면
`lib/sessionScore.ts`의 `computeCompositeScore()` 값만 바꾸면 됩니다.

## 19. 2026-09-02 (10) "자기소개→팀플" 꼬리질문 재검증 — 실전 모드 버그 발견/수정

**결론부터**: 재검증하다가 진짜 버그를 하나 더 찾았습니다. "자기소개에서 팀플 언급하면

- 3단계 체인(자기소개→team_project→tp_conflict_tier1→tp_conflict_tier2)이 실제로 정확히
  이어지는 것을 재현.

**질문/꼬리질문 구조 설명 문서**: `QuestionBankExplained.md`(대분류/꼬리질문/마무리 구조,

## 20. 2026-09-02 (11) 꼬리질문 40개를 대분류로 승격 — 다양성 개선

자세한 내용은 `log/2026-09-02_작업로그.txt`의 "[17차 작업]"에 있습니다.

**요청**: "꼬리질문이 잘 안 되고 대분류 30개만 돌고 끝나는 느낌, 중요한 꼬리질문이면
대분류로 빼놨다가 실제로 꼬리질문에서 나오면 그때 자리를 빼도 될 것 같다"

**한 것**: 꼬리질문 전용 67개 전체를 검토해서, 문장에 その/それ/この 같은 지시어로 "직전
답변 내용"을 가리키는지 확인했습니다.
- 지시어로 맥락을 가리키는 27개(예: "その中で、あなたが担当した部分は何ですか。")는
  맥락 없이 물으면 어색해지므로 그대로 꼬리질문 전용으로 남겼습니다.
- 지시어 없이 그 자체로 완결된 **40개**(예: "チームメンバーの意見が強く対立したとき、
  どのように解決しましたか。")는 **대분류로 승격**했습니다. id는 그대로라
  follow_ups.txt의 꼬리질문 대상으로도 계속 유효하고, 같은 세션에서 실제로 꼬리질문으로
  등장하면 이미 예정돼 있던 대분류 자리는 자동으로 빠집니다(요청하신 그대로).

승격되면서 기존 질문과 겹치게 된 것들(그리고 검토 중 발견한 기존 중복 — weakness/
strengths_and_weaknesses)까지 9개 그룹으로 묶어 근접 중복도 막았습니다.

**결과**: 대분류 175→215개(꼬리질문 전용 67→27개, 전체 은행 247개는 변동 없음 — 태그만
이동). 세션당 후보 풀이 연습 모드 174→214개, 실전 소프트웨어 165→205개, 실전 반도체
127→159개로 크게 늘어 다양성이 개선됩니다.

Node로 모드/트랙 4가지 조합 × 100회 시뮬레이션(중복 없음 확인), self_intro→team_project
체인 회귀 확인, `npx tsc --noEmit` 통과까지 확인했습니다.
