# 예상 질문·꼬리질문 추출용 프롬프트 (prompt_question_extraction.md)

> 개인 모의면접 준비 자료(자기소개서, 모의면접 대화록, 예상 답변 노트 등)를 다른 AI에게 주고
> "질문·꼬리질문만" 뽑아내게 할 때 그대로 복사해서 쓰는 프롬프트입니다. 이 파일 자체에는 특정
> 지원자의 개인정보가 전혀 들어있지 않으므로 git에 커밋해도 됩니다 (`readme_5.md` §5의 4갈래
> 체계에서는 ①·②를 만들기 위한 "도구"에 해당하며, 결과물은 반드시 같은 체크리스트를 통과한 뒤
> `data/drafts/`를 거쳐 `data/questions.json` / `public/data/follow_ups.txt`에 병합합니다).

---

## 사용법

1. 아래 코드 블록 전체를 복사합니다.
2. 맨 아래 `[여기에 원본 자료 붙여넣기]` 부분에, 정리하고 싶은 원본 자료(모의면접 대화록, 자기소개서,
   예상 답변 노트 등 — 실명·학교명이 들어있어도 상관없습니다. 프롬프트가 알아서 걸러냅니다)를
   통째로 붙여넣습니다.
3. AI의 답변으로 나온 결과를 `data/drafts/questions_verN.json`(또는 `.md`)으로 저장합니다.
4. 결과물을 사람이 한 번 더 검토한 뒤 (특히 "제외 규칙"이 실제로 잘 지켜졌는지), `data/questions.json`
   과 `public/data/follow_ups.txt`에 필요한 부분만 병합합니다.

---

## 프롬프트

```text
당신은 "일본 취업 모의면접 자료에서 면접 질문 데이터만 추출하는" 전문 편집자입니다.

# 배경
아래에 원본 자료(모의면접 대화록, 자기소개서, 예상 답변 노트 등)가 주어집니다. 이 자료에는
지원자 개인의 실제 답변, 이름, 학교명, 특정 장소나 일화, 프로젝트의 정확한 수치 등이 섞여
있을 수 있습니다. 이 자료는 "Voice Interview JP"라는 일본어 면접 연습 앱의 질문 은행
(data/questions.json)과 꼬리질문 규칙(public/data/follow_ups.txt)에 넣을 후보를 만들기 위한
재료일 뿐입니다.

# 반드시 지킬 것 (제외 규칙)
아래 항목은 결과물에 절대 포함하지 마세요. 원본에 있어도 전부 제거하거나 일반화하세요.
- 지원자의 실명, 출신 학교명
- 특정 장소·특정 일화(예: 특정 지명, 특정 사건, 특정 날짜의 여행 등)가 드러나는 표현
- 병역(군 복무) 등 개인 신상과 결부되는 민감한 주제
- 특정 회사명이 그대로 노출되는 문장
- 실제 프로젝트의 정확한 수치·점수·퍼센트 등 식별 가능한 성과 지표
  (필요하면 "높은 정확도" 같은 일반화된 표현으로만 남기세요)
- **지원자 개인의 실제 답변 내용 그 자체.** 질문/꼬리질문 문장만 남기고, "이 질문에 지원자가
  어떻게 대답했는가"는 절대 결과물에 넣지 마세요.

# 할 일
원본 자료를 처음부터 끝까지 읽고, 다음 두 가지만 추출하세요.

1. **메인 질문(예상 질문)**: 면접관이 던진(또는 던질 법한) 독립적인 질문 문장.
   - 같은 내용을 여러 번 다르게 표현한 경우, 가장 자연스럽고 실제 면접관이 쓸 법한 경어
     (です・ます체) 문장 하나로 통합하세요.
   - 각 질문에 다음 필드를 붙이세요.
     - `id`: 영문 소문자 slug (단어_단어 형태), 이 목록 안에서 유일해야 함
     - `category`: `personality`(인성/자기PR) | `technical`(전공·기술·업무 경험) |
       `culture_fit`(지망동기·회사이해·생활적응·직업관) | `reverse`(역질문 유도) 중 하나
     - `expectedDurationSec`: 사실 확인성 단답이면 60, 사례·설명이 필요하면 90
     - `textJa`: 일본어 질문 문장만 (です・ます체, 한국어 번역이나 난이도 태그 없이)
     - `tags`: 주제를 나타내는 영문 태그 배열. 이 질문이 다른 질문 뒤에 이어지는 꼬리질문
       성격이면 `"follow_up"` 태그를 추가로 붙이세요.

2. **꼬리질문 규칙 후보**: 원본에서 "어떤 답변 뒤에 어떤 꼬리질문이 이어졌는지"가 드러나면,
   그 관계를 일반화해서 규칙으로 만드세요. 특정 일화에 묶인 꼬리질문(예: "그 카페는 어디에
   있었나요?")은 재사용할 수 없으므로 버리고, 여러 지원자에게 재사용 가능한 형태로만 남기세요
   (예: "그 힘을 다른 상황에서도 발휘한 적이 있나요?"는 재사용 가능, "그 외국인 부부는 몇 분
   동안 길을 헤맸나요?"는 특정 일화 종속이므로 버림).
   - 각 규칙은 `원래질문id | 감지할키워드1,감지할키워드2 | 다음질문id | 우선순위` 형식으로
     작성하세요 (`public/data/follow_ups.txt`와 동일한 형식).
   - 키워드는 그 메인 질문에 대한 "전형적인 답변"에 자연스럽게 등장할 법한 일본어 단어로
     추정해서 넣으세요 (원본에 실제 등장한 단어가 있으면 우선 사용).
   - 특정 키워드 유무보다 "이 질문 뒤에는 항상 이 꼬리질문이 온다"에 가까운 경우, 그 사실을
     별도로 주석(#)으로 남기세요 — 지금 앱의 규칙 엔진은 "키워드가 있을 때만" 발동하는 방식만
     지원하기 때문입니다.

# 출력 형식
아래 두 섹션으로 나눠서 출력하세요.

## A. 메인 질문 (JSON)
\`\`\`json
{
  "questions": [
    { "id": "...", "category": "...", "expectedDurationSec": 60, "textJa": "...", "tags": ["..."] }
  ]
}
\`\`\`

## B. 꼬리질문 규칙 후보 (텍스트, 주석 포함 가능)
\`\`\`
# 원래질문id | 감지할단어1,감지할단어2 | 다음질문id | 우선순위
...
\`\`\`

마지막으로, 위 "반드시 지킬 것" 규칙을 스스로 다시 검토해서, 실명·학교명·특정 장소/일화·병역·
회사명·정확한 수치·개인 실제 답변이 결과물에 하나도 남아있지 않은지 확인했다는 점을 한 줄로
확인해 주세요.

# 원본 자료
[여기에 원본 자료 붙여넣기]
```

## 참고

- 이 프롬프트는 `data/questions_ver1.json`(메인 질문 45개)과 `data/drafts/questions_ver2_followups.md`
  (꼬리질문 규칙 후보)를 만들 때 실제로 적용한 기준을 일반화한 것입니다. 두 결과물을 예시로
  참고하면 출력 형식을 더 쉽게 감 잡을 수 있습니다.
- 결과물은 AI가 만든 "후보"일 뿐이므로, 병합 전 반드시 사람이 한 번 더 훑어보고 `readme_5.md` §5의
  체크리스트로 개인정보·민감정보가 없는지 확인하세요.
