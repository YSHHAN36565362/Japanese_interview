## 4. "예전에 있던 기능들이 어디 갔냐" — 로컬이 origin보다 11커밋 뒤처져 있었음

사용자가 "소프트웨어/반도체 지원 직무 선택", "음성 사운드 조절" 같은 예전 기능이 안 보인다고
질문 — 조사해보니 **기능이 삭제된 게 아니라 로컬 main이 origin/main보다 11개 커밋 뒤처져
있었음**. `git log origin/main`에 로컬에 없는 커밋들이 있었고(`알고리즘 업데이트`,
`Merge origin/main: combine job-track/rate-pitch features with resume upload + follow-up
algorithm work` 등), diff로 보니 **61개 파일, 11,019줄**이 통째로 로컬에 없었음:

- 소프트웨어/반도체/기본 지원 직무 트랙 선택 (`lib/questionBank.ts`, `app/interview/page.tsx`)
- TTS 볼륨/속도/톤 조절 (`useSpeechSynthesis.ts`), 파형 표시(`VoiceWaveform.tsx`)
- .docx 이력서 업로드 + 파싱 + 맞춤 질문/꼬리질문 자동 생성 (`app/interview/resume`,
  `app/api/resume/parse`, `lib/resume/*`)
- STT 보정 사전 직접 관리 UI (`CustomTermManager.tsx`)

**처리**: 이번 세션에서 만든/고친 것(문법 교정 모드, 정리, 디자인 1차)을 `git stash push -u`로
안전하게 보관한 뒤, `git fetch` + `git merge origin/main`으로 fast-forward 병합(충돌 없음,
로컬 main이 origin의 순수 조상이었기 때문). 이후 `npm install`로 새 의존성(jszip,
fast-xml-parser 등) 설치.

- 스태시는 아직 저장소에 남아 있음: `stash@{0}: "pre-merge snapshot: grammar mode + cleanup
  + design work before pulling origin/main"`. 필요 없으면 `git stash drop`으로 지워도 됨
  (§1~§3 작업물은 이미 §5에서 새 코드베이스 위에 다시 적용됐으므로 내용 자체는 안전).

## 5. 병합된 코드베이스 위에 §1~§3 작업 재적용

원격 코드베이스가 로그인 플로우(`router.replace('/login')` 등)까지 포함해 완전히 다른
버전이라, "로그인/시작 로직은 건드리지 말고 그대로 두라"는 사용자 지시에 따라 인증 관련
변경은 재적용하지 않고, 아래만 다시 적용:

- 문법 교정 모드(§1) 전체를 새 `useInterviewMachine.ts`/`constants.ts`/`InterviewRoom.tsx`
  구조에 맞게 재연결
- 결과 페이지 `LikeButton` 제거, `RoomControls`/`InterviewStage` 중복 버튼 제거(§2)
- `RoomControls` 그룹+구분선, 로그인 카드 중앙 정렬(§3) — 단, 로그인 에러 메시지 한국어 폴백은
  "로직은 최신 커밋 그대로 두라"는 지시에 따라 되돌림(레이아웃 스타일만 유지)
- 확인: `장음 인식 안정성` 버그는 이 코드베이스엔 원래 없었음(`computeSessionScore`가 저장된
  컬럼이 아니라 텍스트에서 매번 다시 계산하는 방식이라 해당 버그 자체가 성립 안 함)

## 6. 사용자 시작 흐름 두 차례 조정 (§5 이후, §7 이전)

1. "마이페이지에서 고유번호 입력, 모드선택/면접은 그냥 되게" 요청 → 세션이 없으면 조용히
   익명 로그인 후 진행하도록 시도, 실패 시에만 `/login`으로 폴백
2. "그래도 로그인 화면이 뜬다" → 익명 로그인 실패 시의 `/login` 리다이렉트 폴백까지 완전히
   제거, 로컬 전용 id(`crypto.randomUUID()`)로 오프라인 게스트 진행하도록 변경(`/login`
   화면을 절대 보지 않게 함)

**이 두 변경은 §7 직전에 사용자가 "원격 최신 커밋 로직으로 되돌리라"고 명시적으로 요청해
전부 되돌렸습니다.** 현재 `app/interview/page.tsx`, `useInterviewMachine.ts`의 인증 체크는
origin/main 병합 시점 그대로(`router.replace('/login')`)입니다.

## 9. 꼬리질문 기능 완전 제거 + "연습할 주제" 카테고리 체크박스 신규 도입

"꼬리질문은 로직이 제대로 진행 안 되는 것 같다"는 피드백으로, 답변 키워드로 자동으로 이어지던
꼬리질문 기능을 코드베이스에서 **완전히 삭제**하고, 대신 세션 시작 전에 "연습할 주제"를
체크박스로 직접 고르는 화면을 새로 만들었습니다. 모드(연습/실전/기술면접)와 지원 직무(소프트
웨어/반도체/기본) 선택 흐름은 그대로 유지하고, 그 다음 단계로 카테고리 체크박스를 추가하는
방식으로 넣었습니다(사용자가 "기존 흐름 유지 + 체크박스 단계 추가"를 선택).

### 9-2. 새 분류 체계 — `topicCategory` (13종)

기존 `category`(personality/technical/culture_fit/reverse, 4종)보다 세분화된 주제 분류를

## 10. "대분류 208개인데 왜 세션엔 30개만 나오냐" — poolSize 캡 제거 + 관련 버그 수정

§9에서 만든 카테고리 체크박스 화면 자체는 잘 동작했지만, 세션에 실제로 나오는 개수(Y)가
모드별 `poolSize`(연습 30 / 실전 28 / 기술면접 24)에 캡이 걸려 있어서, 헤더에 뜨는
"(대분류 총 208개)"와 계속 안 맞아 혼란스럽다는 피드백을 받았습니다.

### 10-1. poolSize 캡 완전 제거

- `lib/questionBank.ts`의 `sampleMainQuestions()`에 `opts.dedupeGroups` 파라미터를 추가하고,
  `useInterviewMachine.ts`에서 `poolSize` 대신 `Infinity`를 넘기도록 바꿨습니다 — 이제
  연습/기술면접/실전(소프트웨어·반도체) 전 모드에서 **체크박스로 고른 주제에 해당하는 질문을
  전부** 보여줍니다. `dedupeGroups: false`도 함께 넘겨서, "스트레스 해소법" 류의 비슷한
  질문끼리 하나로 합치던 group 중복 제거도 이 경우엔 껐습니다(고른 개수와 실제 나오는
  개수가 정확히 일치해야 한다는 요청 때문 — §4의 group 필드 자체는 그대로 살아있고, 나중에
  다시 필요해지면 `dedupeGroups`를 안 넘기면 됩니다).
- 면접방 헤더의 "질문 X / Y (대분류 총 Z개)"에서 뒤의 "(대분류 총 Z개)" 표시를 제거했습니다
  (`RoomHeader.tsx`) — Z는 세션/모드와 무관한 전체 은행 크기라 애초에 이 혼란의 원인이었고,
  이제 Y 자체가 "내가 고른 주제의 전체 개수"라 별도 참고값이 필요 없어졌습니다.

### 10-2. 발견한 버그 — 기술 면접 모드에서 topicCategory 필터가 옛 category 필드에 가로막힘

수정하는 김에 원인을 조사하다가, **기술 면접 모드에서 체크박스로 특정 주제를 골라도 그 중
일부 질문은 절대 안 나오는 버그**를 발견해 같이 고쳤습니다. 예를 들어 "반도체 현장 적응"
(5문항: `cleanroom_attitude`, `equipment_trouble_response`, `detail_oriented_work_attitude`,
`client_site_dispatch_work`, `physical_stamina_concern`)을 체크해도 실제로는 2개만 나올 수
있었습니다 — `MODE_TO_CATEGORY.technical = ['technical']`이라는 옛(굵은) 분류 필터가 먼저
걸려서, `category`가 `culture_fit`/`personality`로 남아있는 나머지 3개는 `topicCategory`
체크와 무관하게 애초에 후보에서 빠졌기 때문입니다. `sampleMainQuestions()`를 고쳐서,
`topicCategories`가 주어지면 옛 `categories` 굵은 분류는 아예 무시하고 `topicCategory`
기준으로만 거르도록 했습니다. 브라우저로 "반도체 현장 적응"만 체크하고 기술 면접을
시작해서 "질문 1/5"로 5개 전부 나오는 것을 직접 확인했습니다.

### 10-3. "실전모드 기본에서는 IT문제 안나오게" — it_training_reason 제거

`기본` 트랙 고정 질문 목록(`BASIC_TRACK_QUESTION_IDS`)에서 "日本ＩＴ研修に参加した理由を
教えてください"(`it_training_reason`)를 뺐습니다 — 12개 → 11개. IT 연수 프로그램 참가
이유를 묻는 질문이라 소프트웨어/반도체 지망생 전용 느낌이 강해서, 지원 직무를 특정하지
않는 "기본" 트랙에는 안 어울린다고 판단했습니다.

### 10-4. "소프트웨어(N문제)"처럼 실제 개수를 버튼에 표시

`lib/questionBank.ts`에 `getTrackQuestionCount(track)`(실전 모드 지원 직무 버튼용)와
`getModeQuestionCount(mode)`(연습/기술면접 모드 카드용)를 추가해서, 실제 데이터 기준으로
계산한 개수를 화면에 그대로 보여줍니다(하드코딩 안 함 — 나중에 질문이 추가/삭제돼도 항상
정확). 현재 실측값: 기본 11문제, 소프트웨어 197문제, 반도체 158문제, 연습 모드 최대
207문항, 기술 면접 최대 78문항. 모드 카드의 "질문 수" 상세 항목도 고정된 숫자("최대
30문항" 등) 대신 이 계산값을 쓰도록 바꿨습니다.

### 확인한 것

- `npx tsc --noEmit`, `npm run build` 통과
- 브라우저(게스트)로 직접 확인: 모드 선택 페이지에 "최대 207문항"/"최대 78문항" 표시,
  지원 직무 버튼에 "기본(11문제)/소프트웨어(197문제)/반도체(158문제)" 표시, 실전
  모드(반도체) "반도체 현장 적응"만 체크 시 자기소개+5문항+역질문="질문 1/7", 기술 면접
  모드에서 "반도체 현장 적응"만 체크 시 "질문 1/5"로 5개 전부(버그 있던 3개 포함) 나오는
  것, 면접방 헤더에서 "(대분류 총 Z개)" 표시가 사라진 것까지 확인

### 확인 못 한 것 / 남은 일

- 연습 모드에서 전체 선택 시 실제로 207개가 끝까지 이어지는 풀코스 테스트는 안 함(시간이
  매우 오래 걸림) — 처음 몇 문항과 헤더 카운트만 확인
- 커밋은 아직 안 했음

## 11. 한국어 대역(블러) 복원 + 시작 화면 버전 표시 추가

### 11-1. "일본어 블러 아래 한국어 번역" 기능 — 사라진 게 아니라 데이터가 희박했던 것

사용자가 예전에 있던 기능(질문 블러 처리 아래에 한국어 번역도 같이 블러로 보여주는 것)이
사라진 것 같다고 요청 — 확인해보니 `InterviewStage.tsx`/`app/globals.css`의 렌더링 로직
자체는 그대로 살아있었고, 원인은 **`data/questions.json`의 `textKo`(한국어 대역) 필드가
208개 중 57개(약 27%)에만 채워져 있어서, 특히 track 없는 공통 질문·"기본" 트랙 고정
목록에는 아예 하나도 없었다는 것**이었습니다(§9~§10에서 poolSize 캡을 없애 세션에 다양한
질문이 더 많이 섞이게 된 것도 체감상 "안 보인다"는 인상을 키웠을 가능성이 있습니다).

- **`data/questions.json`의 대분류 질문 208개 전부**에 한국어 대역을 새로 채워 넣었습니다
  (기존 57개는 그대로 두고 나머지 151개만 번역해서 추가 — 스크립트로 일괄 적용).
  마무리 전용(`closing`) 질문 5개도 번역 추가.
- 코드에 고정된 질문에도 번역을 추가: `REAL_MODE_INTRO_QUESTION`(자기소개, 실전 모드 항상
  첫 질문), 이력서 자소서 5문항(`RESUME_ESSAY_QUESTIONS`). 이력서 경력/희망직종 질문은
  회사명 등이 매번 바뀌는 동적 문장이라 번역을 넣지 않았습니다.
- `data/Question/*.md` 참고 문서도 재생성해서 한국어 대역이 반영되도록 갱신했습니다.
- 브라우저로 실전 모드(소프트웨어)에서 직접 확인: 일본어 질문 줄과 한국어 번역 줄이 각각
  따로 블러 처리되어 있고, 각각 마우스를 올리면 그 줄만 개별적으로 보이는 것(원래 동작
  그대로)까지 확인했습니다.

### 11-2. 시작 화면에 버전(마지막 업데이트 시각) 표시

값을 손으로 갱신**하는 방식입니다 — 다음에 기능을 추가/수정할 때 이 상수도 함께
업데이트해야 합니다.
