[1차 작업] 꼬리질문이 실제로 전혀 발동하지 않던 진짜 원인 발견/수정 + 전사 지우기 재수정 +
           개인 STT 보정 사전 직접 추가 기능 + 실제 브라우저(로컬+실제 Supabase) 종단 검증
===============================================================

"꼬리질문이 아직도 안 되고, 음성으로 답변한 텍스트가 안 지워지고, 이름 등 카타카나/영어는
인식이 잘 안 되어서 개인 수정이 필요하다"는 제보로 다시 조사했습니다. 이전 회차들에서
Node로 follow_ups.txt 파싱/매칭 로직만 반복 검증했었는데, 이번엔 실제 브라우저 런타임
경로(fetch로 규칙 파일을 불러오는 부분)를 다시 봤더니 진짜 버그가 있었습니다.

[1. 꼬리질문이 전혀 발동하지 않을 수 있던 근본 원인]
lib/questionBank.ts의 loadFollowUps()가 규칙 목록을 이렇게 캐싱하고 있었습니다:
  if (followUpsCache) return followUpsCache
  try { ...fetch 성공 시 결과 저장... } catch { followUpsCache = [] }

문제: 자바스크립트에서 빈 배열 []은 truthy입니다. 즉 세션 중 단 한 번이라도 이 fetch가
실패하거나(네트워크 순간 끊김 등), 응답 내용이 파싱 가능한 규칙을 하나도 못 찾으면
followUpsCache가 []로 굳어버리고, 그 뒤로는 `if (followUpsCache)` 검사를 항상 통과해서
다시는 fetch를 시도하지 않습니다 — 즉 세션 초반에 단 한 번만 실패해도 그 세션 내내
꼬리질문이 영원히 하나도 안 나오게 되는 심각한 버그였습니다. 정확히 사용자가 겪은
증상("꼬리질문이 안 됨")과 일치합니다.

수정: "성공(규칙 1개 이상)"일 때만 캐시하고, 실패하거나 규칙이 0개면 캐시를 비워서
다음 호출 때 다시 시도하도록 고쳤습니다. 여러 곳에서 동시에 부르는 경우를 대비해 진행
중인 Promise 자체를 캐시해 중복 fetch도 막았습니다.

[2. 음성 인식 텍스트가 "안 지워지던" 원인]
이전 회차(2026-09-02)에 "듣는 중이 아닐 때만 transcript만 보여준다"로 한 번 고쳤는데,
그건 "듣는 중"일 때는 여전히 transcript || interimTranscript 방식이라, 마이크가 계속
듣고 있는 도중에 사용자가 키보드로 텍스트를 지워도(draftTranscript가 빈 문자열이 됨)
interimTranscript가 계속 채워지고 있어서 곧바로 다시 나타나 보였습니다 — "지워도 안
지워진다"는 제보와 정확히 일치합니다.

수정: features/interview/components/TranscriptPanel.tsx에서 편집 가능한 답변 박스 값은
이제 상황과 무관하게 항상 transcript(draftTranscript) 하나만 씁니다. 실시간 인식 중인
내용은 박스 안에 섞어 넣지 않고, 박스 아래 별도의 "듣는 중: ..." 미리보기 줄로만
보여줍니다. 이제 키보드로 지우면 마이크가 계속 듣고 있어도 다시 채워지지 않습니다.
※ 이 자동화 환경에는 실제 마이크가 없어 "말하는 도중에 지우기" 상황 자체를 완전히
재현하지는 못했고, 코드 구조상(interimTranscript가 편집 값에 전혀 관여하지 않음) 문제가
근본적으로 발생할 수 없음을 코드 검토로 확인했습니다.

[3. 이름·카타카나·영어 인식 보정을 사용자가 직접 등록하는 기능 신규 추가]
지금까지는 "적용" 버튼으로 사전 등록된 기술 용어 오인식만 자동 제안됐고, 이름처럼
시스템이 모르는 고유명사는 등록할 방법이 없었습니다. 마이페이지에 새 컴포넌트
components/CustomTermManager.tsx를 추가해서, "인식되는 표현 / 올바른 표현 / 분류(이름·
기술 용어·기타)"를 직접 입력해 user_custom_terms에 바로 추가하고, 목록에서 개별 삭제도
할 수 있게 했습니다. 등록해두면 다음 면접부터 normalizeTranscript가 확정 답변에 자동
반영합니다.

[검증 — 실제 브라우저(로컬 서버 + 실제 Supabase 프로젝트)로 종단 확인]
로컬 .env.local을 일시적으로 실제 Supabase 프로젝트 값으로 바꿔서(테스트 후 즉시
플레이스홀더로 복구), 배포를 기다리지 않고 방금 고친 코드를 실제 백엔드로 바로 검증할 수
있게 했습니다.
- 실전 모드(소프트웨어 트랙)로 세션을 만들어 자기소개에 "チームプロジェクトを経験しました"
  라고 실제로 입력하고 답변 완료 → 다음 질문이 정확히 team_project
  ("チームで取り組んだプロジェクトについて教えてください。")로 바뀌는 것을 화면과
  document.querySelector로 직접 확인. 헤더도 "질문 2 / 31 (대분류 총 215개)"로 정확히
  갱신됨.
- 이어서 team_project 답변에 "意見が対立しましたが、話し合って解決しました"라고 입력 →
  다음 질문이 정확히 tp_conflict_tier1로 이어지는 것까지 확인 — 3단계 체인 전체가
  실제 서비스 환경에서 작동함을 증명했습니다.
- 네트워크 탭에서 /data/follow_ups.txt가 200으로 정확히 한 번 로드되는 것도 확인.
- 마이페이지의 "지난 세션"에 방금 진행한 세션이 "real · 답변 2개"로 정확히 나타나 저장도
  정상 확인.
- CustomTermManager로 "スタロ → スター (name)" 추가/삭제를 실제로 실행해 정상 동작 확인.
- 테스트로 만든 세션/답변은 확인 후 curl로 즉시 삭제해 정리. .env.local은 원래
  플레이스홀더 값으로 복구하고 개발 서버 재시작.
- npx tsc --noEmit 통과.
