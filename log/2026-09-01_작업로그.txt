5. 꼬리질문(키워드 감지) 동작 방식 설명 — AI를 쓰지 않는 이유와 원리
===============================================================
질문하신 "답변에서 정한 단어가 나오면 꼬리질문을 한다"는 기능은 이미
구현되어 있고, 다음처럼 동작합니다.

  1) 사용자가 메인 질문에 음성으로 답하고 "답변 제출"을 누릅니다.
  2) 브라우저가 인식한 텍스트(음성 인식 결과, 서버로 전송되지 않음)를 그대로
     lib/followUp.ts의 matchFollowUpRule() 함수에 넘깁니다.
  3) 이 함수는 data/questions.json의 "followUps" 배열에서
     parentId가 지금 질문과 같은 규칙들을 모아, keywords 배열 중 하나라도
     답변 텍스트에 포함되어 있는지 answerText.includes(keyword) 로만 검사합니다.
     — LLM 호출도, 서버 요청도 전혀 없는 단순 문자열 포함 검사입니다.
  4) 조건을 만족하는 규칙이 있으면 targetId로 지정된 질문을 바로 다음
     질문으로 보여줍니다. 이미 이번 세션에서 물어본 꼬리질문은 다시
     묻지 않습니다 (askedFollowUps 상태로 추적).
  5) 여러 규칙이 동시에 맞으면 priority 숫자가 큰 규칙을 우선합니다.

[저장 위치]
  꼬리질문 규칙도 질문과 같은 파일, data/questions.json 안의
  "followUps" 배열에 넣으면 됩니다. 새 질문을 추가한 뒤 그 질문의 id를
  parentId/targetId로 참조하는 식으로 계속 확장할 수 있습니다.

6. 실전 모드 첫 질문 고정 ("간단한 자기소개를 부탁드립니다")
===============================================================
요청하신 대로 이 질문은 사용자가 수정하는 data/questions.json에는 넣지
않고, 코드에 직접 고정했습니다.

  위치: lib/questionBank.ts → REAL_MODE_INTRO_QUESTION 상수
  내용: "簡単に自己紹介をお願いします。" (간단한 자기소개를 부탁드립니다)

실전(real) 모드를 시작하면 이 질문이 무조건 맨 처음에 나오고, 이후
질문 5개가 무작위로 이어집니다. data/questions.json을 아무리 고쳐도
이 첫 질문 자체는 바뀌지 않습니다(의도된 동작).

===============================================================
7. 질문 순서가 그대로였던 문제 — 셔플 적용
===============================================================
기존에는 Supabase에서 created_at 오름차순으로 항상 같은 순서/조합의
질문 6개만 나왔습니다. 이제 매 세션 시작 시 lib/questionBank.ts의
shuffle() 함수(Fisher–Yates)로 무작위로 섞은 뒤 6개(실전 모드는 고정
자기소개 1개 + 5개)를 뽑습니다. data/questions.json에 질문을 더 추가할수록
매번 다른 조합이 나옵니다.

8. JLPT 난이도 구분 삭제 / 한국어 번역 제거 / 경어 통일 확인
===============================================================
"난이도별로 질문이 달라지는 게 아니고, 면접관은 항상 경어로 물어보니
JLPT 구분은 필요 없다. 한국어 질문 없이 일본어만 보여달라"는 요청에 따라:

- data/questions.json에서 jlptLevel, keigoRequired, textKo(한국어 번역)
  필드를 전부 제거했습니다. 이제 질문 객체는 id/category/
  expectedDurationSec/textJa/tags만 가집니다.
- 면접 진행 화면(app/interview/run)에서 한국어 번역 표시 코드를 제거했습니다.
- 레벨 체크 화면의 JLPT 자가 신고(N1~N5)는 그대로 남겨뒀습니다. 이건
  질문 필터링용이 아니라 "경어 모드(keigo_mode)" 추천에 계속 쓰이기
  때문입니다 — 사용자가 경어를 어려워하면 보통체로 먼저 연습하게 해주는
  기능이라 남겨두는 게 맞다고 판단했습니다. 필요 없다고 하시면 다음에
  같이 제거해도 됩니다.
- 질문 문구가 전부 경어(です・ます체)인지 다시 확인했습니다. 예:
  「自己紹介をお願いします。」「〜について教えてください。」「〜ですか。」
  전부 정중체이며, 새 고정 질문("簡単に自己紹介をお願いします。")도
  마찬가지로 경어입니다. 별도 수정 없이 이미 요구사항을 만족합니다.
