5. 꼬리질문(키워드 감지) 동작 방식 설명 — AI를 쓰지 않는 이유와 원리
===============================================================
질문하신 "답변에서 정한 단어가 나오면 꼬리질문을 한다"는 기능은 이미
구현되어 있고, 다음처럼 동작합니다.

  1) 사용자가 메인 질문에 음성으로 답하고 "답변 제출"을 누릅니다.
  2) 브라우저가 인식한 텍스트(음성 인식 결과, 서버로 전송되지 않음)를 그대로
     lib/followUp.ts의 matchFollowUpRule() 함수에 넘깁니다.
  3) 이 함수는 data/questions.json의 "followUps" 배열에서
     parentId가 지금 질문과 같은 규칙들을 모아, keywords 배열 중 하나라도
     답변 텍스트에 포함되어 있는지 answerText.includes(keyword) 로만 검사합니다.
     — LLM 호출도, 서버 요청도 전혀 없는 단순 문자열 포함 검사입니다.
  4) 조건을 만족하는 규칙이 있으면 targetId로 지정된 질문을 바로 다음
     질문으로 보여줍니다. 이미 이번 세션에서 물어본 꼬리질문은 다시
     묻지 않습니다 (askedFollowUps 상태로 추적).
  5) 여러 규칙이 동시에 맞으면 priority 숫자가 큰 규칙을 우선합니다.

[저장 위치]
  꼬리질문 규칙도 질문과 같은 파일, data/questions.json 안의
  "followUps" 배열에 넣으면 됩니다. 새 질문을 추가한 뒤 그 질문의 id를
  parentId/targetId로 참조하는 식으로 계속 확장할 수 있습니다.

6. 실전 모드 첫 질문 고정 ("간단한 자기소개를 부탁드립니다")
===============================================================
요청하신 대로 이 질문은 사용자가 수정하는 data/questions.json에는 넣지
않고, 코드에 직접 고정했습니다.

  위치: lib/questionBank.ts → REAL_MODE_INTRO_QUESTION 상수
  내용: "簡単に自己紹介をお願いします。" (간단한 자기소개를 부탁드립니다)

실전(real) 모드를 시작하면 이 질문이 무조건 맨 처음에 나오고, 이후
질문 5개가 무작위로 이어집니다. data/questions.json을 아무리 고쳐도
이 첫 질문 자체는 바뀌지 않습니다(의도된 동작).

===============================================================
7. 질문 순서가 그대로였던 문제 — 셔플 적용
===============================================================
기존에는 Supabase에서 created_at 오름차순으로 항상 같은 순서/조합의
질문 6개만 나왔습니다. 이제 매 세션 시작 시 lib/questionBank.ts의
shuffle() 함수(Fisher–Yates)로 무작위로 섞은 뒤 6개(실전 모드는 고정
자기소개 1개 + 5개)를 뽑습니다. data/questions.json에 질문을 더 추가할수록
매번 다른 조합이 나옵니다.

8. JLPT 난이도 구분 삭제 / 한국어 번역 제거 / 경어 통일 확인
===============================================================
"난이도별로 질문이 달라지는 게 아니고, 면접관은 항상 경어로 물어보니
JLPT 구분은 필요 없다. 한국어 질문 없이 일본어만 보여달라"는 요청에 따라:

- data/questions.json에서 jlptLevel, keigoRequired, textKo(한국어 번역)
  필드를 전부 제거했습니다. 이제 질문 객체는 id/category/
  expectedDurationSec/textJa/tags만 가집니다.
- 면접 진행 화면(app/interview/run)에서 한국어 번역 표시 코드를 제거했습니다.
- 레벨 체크 화면의 JLPT 자가 신고(N1~N5)는 그대로 남겨뒀습니다. 이건
  질문 필터링용이 아니라 "경어 모드(keigo_mode)" 추천에 계속 쓰이기
  때문입니다 — 사용자가 경어를 어려워하면 보통체로 먼저 연습하게 해주는
  기능이라 남겨두는 게 맞다고 판단했습니다. 필요 없다고 하시면 다음에
  같이 제거해도 됩니다.
- 질문 문구가 전부 경어(です・ます체)인지 다시 확인했습니다. 예:
  「自己紹介をお願いします。」「〜について教えてください。」「〜ですか。」
  전부 정중체이며, 새 고정 질문("簡単に自己紹介をお願いします。")도
  마찬가지로 경어입니다. 별도 수정 없이 이미 요구사항을 만족합니다.

주시면 됩니다.)

[새로 만든 것]
- components/CameraPreview.tsx
  → Zoom의 "셀프 뷰"처럼 화면 위에 떠 있는 내 카메라 미리보기 창.
  → 몸통을 드래그하면 위치 이동, 오른쪽 아래 모서리를 드래그하면 크기 조절

  → 서버로 전송되지 않고 브라우저 안에서만 스트리밍됩니다.

  → 카메라가 꺼져 있으면 "화상 녹화" 버튼은 비활성화(회색, 클릭 불가) 처리.
  → 녹화 중일 때는 버튼이 빨간색으로 바뀌고 은은하게 깜빡이는 효과로

  → 화상/음성 녹화의 공통 로직. MediaRecorder로 녹화하고, 중지 버튼을 누르면
    즉시 Blob → 브라우저 다운로드로 이어집니다.
  → ⚠️ 중요: Supabase Storage에는 전혀 업로드하지 않습니다. 말씀하신 대로
    "서버에 한번 올라갔다 저장되는 방식"이 아니라, 100% 로컬(사용자 기기)
    저장입니다. 무료 티어 용량과 무관합니다.
  → 녹화 종료 시 파일명 예: interview-video-1735689600000.webm,
    interview-audio-1735689600000.webm (브라우저의 기본 다운로드 폴더로 저장됨,
    다운로드 위치는 브라우저 설정을 따릅니다)

  질문 카드도 Zoom의 참가자 화면처럼 어두운 톤 타일(.zoom-tile)로 바꾸고
  "면접관" 라벨과 동그란 아바타를 추가했습니다.

[Chrome 테스트 결과]

- 카메라 미리보기 창 모서리로 크기 조절 → 정상.

- 최초 발견된 버그: "면접관" 이름표가 "다시 듣기(TTS)" 버튼과 겹쳐 보이는
  문제 → .zoom-tile의 아래쪽 여백을 늘려서 즉시 수정, 재확인 완료.

[참고] 이 세션에는 실제 마이크/카메라 장치가 없는 테스트 환경이라, 실제

[2차 작업] 14. 꼬리질문 조건을 JSON이 아니라 텍스트 파일로 분리
===============================================================
"data/questions.json 말고, 텍스트 형식으로 어떤 단어가 나오면 지정한 질문이
나오게 해달라"는 요청에 따라, 꼬리질문 규칙만 별도의 일반 텍스트 파일로
옮겼습니다.

  새 위치: /Users/ys/Downloads/etc/GitHub/Japanese_interview/public/data/follow_ups.txt

[형식 — JSON 문법 필요 없음]
  원래질문id | 감지할단어1,감지할단어2,... | 다음질문id | 우선순위(선택)

예시:
  team_project | チーム,プロジェクト,担当 | role_detail | 1

- '#'으로 시작하는 줄과 빈 줄은 무시됩니다.
- 원래질문id / 다음질문id는 data/questions.json에 있는 질문의 "id" 값을 그대로 씁니다.
- 이 파일은 public/ 폴더 안에 있어서, 브라우저가 fetch로 직접 읽어옵니다.
  즉 이 파일만 고쳐도 (data/questions.json을 안 건드려도) 꼬리질문 규칙을
  바로 추가/수정할 수 있습니다.

data/questions.json에서는 followUps 배열을 제거했습니다 (이제 안 씀).
질문(questions) 자체는 여러 필드(category, expectedDurationSec 등)가 있어
구조가 필요하므로 JSON 그대로 유지했습니다.

[동작 방식 — 다시 요약]
사용자가 답한 텍스트에 follow_ups.txt에 적힌 단어가 하나라도 포함되어 있으면
(단순 문자열 포함 검사, AI 아님) 그 줄에 지정한 다음 질문으로 넘어갑니다.
lib/questionBank.ts가 이 파일을 fetch해서 파싱하고, lib/followUp.ts가 매칭합니다.

[3차 작업, 같은 날] 15. Zoom형 프런트엔드 가이드 기반 면접 진행 화면 전면 리팩터링
===============================================================
공유해주신 zoom_style_frontend_implementation_guide.md(Manus 작성)를 그대로 기준 삼아
/interview/run/[sessionId] 화면 전체를 다시 만들었습니다. "모든 범위"라고 하신 대로,
