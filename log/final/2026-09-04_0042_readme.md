## 4. 이번 회차(2026-09-04)에 한 일 — 상세

### 4-1. 🔴 면접이 첫 질문에서 통째로 멈춰버리던 버그 (신규 발견 · 수정)

**증상**: 실전 모드를 시작하면 "면접관이 질문을 읽고 있습니다" 상태에서 영원히
멈추고, 마이크·"답변 완료" 버튼이 전부 비활성인 채로 아무것도 못 하게 됩니다.

**원인**: TTS의 VOICEVOX 경로(`features/interview/hooks/useSpeechSynthesis.ts`)에
**`onEnd` 콜백이 절대 호출되지 않는 막다른 길이 3군데** 있었습니다. 상태 기계
(`useInterviewMachine.ts`)는 "TTS가 끝났다"는 신호(`onEnd`)를 받아야만 다음 단계
(`listening`)로 넘어가는데, 그 신호가 영영 안 오니 화면이 얼어붙습니다. 게다가
VOICEVOX 합성 요청(외부 무료 서버라 느리거나 죽어있을 수 있음)에 **타임아웃이 아예
없어서**, 응답이 안 오면 무한정 기다렸습니다.

**수정 (2중 안전장치)**:

1. `useSpeechSynthesis.ts` — VOICEVOX에 **8초 워치독** 추가. 8초 안에 합성이 안 끝나면
   요청을 취소하고 즉시 브라우저 기본 음성으로 대체 재생합니다. 성공·실패·타임아웃 중
   무엇이 먼저 오든 딱 한 번만 처리되도록 `settled` 플래그로 막았습니다.

```ts
const VOICEVOX_TIMEOUT_MS = 8000
const finishWithNative = () => {
  if (settled || !isCurrent()) return
  settled = true
  controller.abort(); abortRef.current = null
  speakNative(text)          // 브라우저 음성으로 대체 → onEnd가 반드시 발생
}
const watchdog = window.setTimeout(finishWithNative, VOICEVOX_TIMEOUT_MS)
```

2. `useInterviewMachine.ts` — 그래도 혹시 모를 경우를 대비해 **상태 기계 자체에 15초
   워치독** 추가. `interviewerSpeaking` 상태가 15초를 넘기면 원인과 무관하게 강제로
   답변 단계로 넘어갑니다. 즉 **이제는 TTS가 어떤 식으로 실패해도 면접이 멈추지
   않습니다.**

```ts
useEffect(() => {
  if (phase !== 'interviewerSpeaking') return
  const timer = window.setTimeout(() => {
    setPhase((p) => (p === 'interviewerSpeaking' ? (sttSupported ? 'listening' : 'questionReady') : p))
  }, 15000)
  return () => window.clearTimeout(timer)
}, [phase, sttSupported, currentQuestion?.id])
```

**검증**: 실제 브라우저에서 질문 표시 후 화면이 "질문을 확인하고 마이크를 눌러 답변을
시작하세요"로 정상 전환되고 `답변 완료` 버튼이 활성화(`disabled: false`)되는 것을 확인.

### 4-2. ✅ 꼬리질문 3단 체인 — 실제 브라우저에서 종단 검증

사용자의 핵심 질문("답변에 어떤 단어가 나오면 그 단어에 관한 질문이 다음에 나오는가?")에
대한 직접 증거입니다. 실전 모드(소프트웨어 트랙) 세션에서 실제 Supabase에 저장하며 확인:

| 단계 | 답변에 넣은 말 | 실제로 나온 다음 질문 |
|---|---|---|
| 1 | 자기소개에 **「チーム」** 포함 | `team_project` → "チームで取り組んだプロジェクトについて教えてください。" (배지: **꼬리 질문**, 헤더: 질문 2 / 30) |
| 2 | 그 답변에 **「対立」** 포함 | `tp_conflict_tier1` → "チームメンバーの意見が強く対立したとき、具体的にどのように解決しましたか。" |
