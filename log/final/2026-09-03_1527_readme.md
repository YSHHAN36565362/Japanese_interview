## 1. 프로젝트가 뭔가요

**Mensetsu Dojo**(구 "Voice Interview JP")는 일본 IT 취업 면접을 일본어로 반복
연습할 수 있는 **완전 무료(0원 운영)** 웹 앱입니다.

- **스택**: Next.js 16(App Router) + React 19 + Supabase(인증/저장) + 브라우저
  Web Speech API(음성 인식/합성). LLM·유료 API를 전혀 쓰지 않고, "AI스러운" 동작(꼬리질문
  판단, STT 보정, 채점)은 전부 **정규식·키워드 매칭 같은 규칙 기반 로직**으로 구현되어
  있습니다.
- **배포**: Vercel(`https://japanese-interview.vercel.app`) + Supabase(무료 티어,
  프로젝트 ref `nnzbepzfketxxnztddbk`). 로컬 저장소는 git 저장소가 아니며, 사용자가 직접
  GitHub Desktop으로 커밋/푸시를 관리합니다.
- **핵심 설계 원칙**: 고유 번호(숫자) 하나로 기기 간 기록을 이어볼 수 있되, 원하면
  "번호 없이 시작하기"(익명 로그인)로 아무 기록도 안 남기고 바로 쓸 수 있음.

## 3. 오늘까지 이어진 주요 구현 과정 (요약)

세션이 여러 날에 걸쳐 진행되어, 흐름을 주제별로 묶어 정리합니다.

1. **UI 기본 골격**: macOS 사파리 느낌 → 검정 단색 테마로 전환, Uiverse.io CSS를
   그대로 붙이지 않고 테마에 맞게 각색(글리치 버튼, 좋아요 버튼, 마이크 테스트 밑줄

2. **음성 파이프라인 안정화**: 마이크 레벨 미터 안 움직이던 버그(AudioContext suspended)

   `getVoices()` 사용), STT 시작 지연으로 초반 말 잘리던 문제(`onstart` 이벤트로
   교정), 자동 문장부호, 음성 파형(웨이브폼) 시각화 추가.
3. **질문 은행 성장**: 여러 회차에 걸쳐 batch2~batch7 + 개별 추가로 210개→247개까지
   확충. 소프트웨어/반도체 트랙 분리, "기본 모드" 고정 목록, 이력서 키워드 매칭까지
   순차적으로 얹음.
4. **꼬리질문 엔진 개선**: 진행률(X/Y)에 꼬리질문이 전혀 안 세지던 버그 수정, 그룹
   (group) 필드로 근접 중복 질문 방지, 안전망(`*`) 규칙 신규 지원, 꼬리질문 40개를
   "지시어 없이도 자연스러운 것" 기준으로 대분류로 승격(다양성 개선), 그리고
   **오늘(2026-09-03) 꼬리질문이 세션 내내 아예 안 뜨게 만들 수 있던 캐싱 버그를
   발견해 수정**(아래 §4 참고).
5. **인프라/백엔드 사고 해결**: 실제 배포본에서 로그인 실패("Email address ... is
   invalid") → Confirm email 설정 문제로 확인, 이어서 Email provider 자체가 잘못
   꺼져 있던 것 발견, 마지막으로 **가장 심각했던 문제 — Supabase의
   `session_answers.question_id`가 아직 uuid 타입인데 코드는 문자열 id를 쓰고
   있어서 모든 답변 저장이 조용히 실패하고 있던 것**을 발견하고 마이그레이션으로
   해결(`supabase/migrate_local_questions.sql`). 이후 실제 배포본에서 로그인→면접→
   저장→결과 화면까지 전체 파이프라인을 Chrome으로 종단 검증 완료.
6. **세션 리포트 채점 로직 재검토**: 정중체/반말체 판정 정규식이 です/ます/だ/である
   사전형만 잡고 있어서 실제 답변 대부분(ます형 활용, 사전형 동사 반말체)을 놓치고

## 4. 오늘(2026-09-03) 해결한 것 — 가장 중요한 회차

### 4-1. 꼬리질문이 세션 내내 전혀 안 나올 수 있던 진짜 원인

`lib/questionBank.ts`의 `loadFollowUps()`가 꼬리질문 규칙 파일(`follow_ups.txt`)을
아래처럼 캐싱하고 있었습니다:

```ts
if (followUpsCache) return followUpsCache
try { ...성공 시 저장... } catch { followUpsCache = [] }
```

자바스크립트에서 **빈 배열 `[]`은 truthy**입니다. 세션 중 단 한 번이라도 이 fetch가
실패하거나 파싱 가능한 규칙을 하나도 못 찾으면 `followUpsCache`가 `[]`로 굳어버리고,
그 뒤로는 `if (followUpsCache)` 검사를 항상 통과해서 **다시는 fetch를 시도하지
않습니다** — 세션 초반에 단 한 번만 실패해도 그 세션 내내 꼬리질문이 하나도 안
나오게 되는 버그였고, 지금까지 반복해서 "꼬리질문이 잘 안 된다"고 느끼셨던 것과
정확히 일치합니다.

**수정**: 성공(규칙 1개 이상)일 때만 캐시하고, 실패/빈 결과면 캐시를 비워 다음 호출 때
다시 시도하도록 했습니다. 동시 호출을 대비해 진행 중인 Promise 자체를 캐시해 중복
fetch도 막았습니다.

### 4-2. 음성으로 답변한 텍스트가 "안 지워지던" 문제

이전 회차에 "듣는 중이 아닐 때만 고치는" 부분 수정을 했었는데, **정작 마이크가 계속
듣고 있는 도중에** 키보드로 텍스트를 지워도 실시간 인식 값(interimTranscript)이 곧바로
다시 채워 넣어서 "지워도 안 지워지는" 것처럼 보이는 문제가 남아있었습니다.

**수정**: `features/interview/components/TranscriptPanel.tsx`에서 편집 가능한 답변
박스 값을 이제 **상황과 무관하게 항상 `transcript`(사용자가 편집하는 값) 하나만** 쓰도록
바꿨습니다. 실시간 인식 중인 내용은 박스 안에 섞지 않고, 박스 아래 "듣는 중: ..."
별도 미리보기 줄로만 보여줍니다. 이제 키보드로 지우면 마이크가 계속 듣고 있어도 절대
다시 채워지지 않습니다.

> ⚠️ 이 자동화 환경에는 실제 마이크가 없어서 "말하는 도중에 지우기" 상황을 완전히
> 재현하지는 못했습니다 — 코드 구조상(interimTranscript가 편집 값에 전혀 관여하지
> 않음) 문제가 근본적으로 재발할 수 없다는 것까지는 코드 검토로 확인했지만, **실제
> 마이크로 한 번 더 확인해주시면 확실합니다.**

### 4-3. 이름·카타카나·영어 인식 보정을 직접 등록하는 기능 신규 추가

지금까지는 "적용" 버튼으로 미리 등록된 기술 용어 오인식만 자동 제안됐고, 이름처럼
시스템이 모르는 고유명사는 등록할 방법이 없었습니다. 마이페이지에
`components/CustomTermManager.tsx`를 새로 추가해서, "인식되는 표현 / 올바른 표현 /
분류(이름·기술 용어·기타)"를 직접 입력해 바로 추가하고, 개별 삭제도 할 수 있게
했습니다. 다음 면접부터 확정 답변에 자동으로 반영됩니다.

### 4-4. 검증 방법 (실제 브라우저 + 실제 Supabase, Chrome 디버깅)

로컬 개발 서버의 `.env.local`을 **일시적으로 실제 Supabase 프로젝트 값으로 바꿔서**
(테스트 직후 즉시 플레이스홀더로 복구), Vercel 배포를 기다리지 않고 방금 고친 코드를
실제 백엔드로 바로 검증했습니다.

1. 실전 모드(소프트웨어 트랙)로 세션 생성 → 자기소개에 "チームプロジェクトを経験
   しました" 입력 → 답변 완료 → **다음 질문이 정확히 `team_project`
   ("チームで取り組んだプロジェクトについて教えてください。")로 바뀌는 것을
   화면과 `document.querySelector`로 직접 확인**. 헤더도 "질문 2 / 31 (대분류 총
   215개)"로 정확히 갱신됨.
2. 이어서 team_project 답변에 "意見が対立しましたが、話し合って解決しました" 입력 →
   **다음 질문이 정확히 `tp_conflict_tier1`로 이어지는 것까지 확인** — 3단계 체인
   전체가 실제 서비스 환경에서 작동함을 증명.
3. 네트워크 탭에서 `/data/follow_ups.txt`가 200으로 정확히 한 번 로드되는 것 확인.
4. 마이페이지 "지난 세션"에 방금 세션이 "real · 답변 2개"로 정확히 나타나 저장도
   정상 확인.
5. `CustomTermManager`로 "スタロ → スター (name)" 추가/삭제 실제 실행 확인.
6. 테스트 세션/답변은 확인 후 curl로 즉시 삭제. `.env.local`은 원래 플레이스홀더로
   복구하고 개발 서버 재시작. `npx tsc --noEmit` 통과.
