# Voice Interview JP — 최종 제안서 ver.3

일본 IT 기업 취업을 준비하는 한국인 지원자를 위한 **완전 무료(0원) 음성 모의 면접 트레이너**.

> `OT.txt` → `readme.md`(1차 기획 + 검토 의견) → `readme_2.md`(1차 최종안)에 이어, **실사용자 규모(동시 5~10명 미만)와 사용자 간 실력 편차(경어 가능/불가, JLPT N1~N4, 장음 발음 약점)** 를 반영해 다시 정리한 최종안입니다.

---

## 1. 목적 및 핵심 원칙

- **목적**: 일본어 음성으로 질문을 듣고, 일본어로 말하며 답변하는 모의 면접을 브라우저에서 무료로 반복 연습.
- **핵심 방향**: AI 면접관(LLM) 없이, 규칙 기반 진행 로직 + 측정 가능한 자가 피드백으로 훈련 도구를 만든다. 여기에 **사용자별 실력 편차를 흡수하는 레벨 체크·난이도 태깅**을 더한다.

### 0원 운영 원칙 (최우선)

- 유료 전환 요소는 처음부터 배제 (LLM API, 유료 STT/TTS, 유료 DB/호스팅 플랜).
- 답변 분석·꼬리질문·피드백·레벨 진단은 전부 **정규식/사전/규칙 기반**으로 클라이언트에서 처리.
- Supabase 무료 티어 + Vercel Hobby(무료)로 고정.
- 꼬리질문은 AI 생성이 아니라 사전 정의 세트 + 조건 매칭 규칙.

### "서버 호출 없음"의 정확한 의미 (정정 유지)

브라우저 `SpeechRecognition`은 API 과금은 없지만, 브라우저·OS에 따라 서버 기반 인식 엔진을 사용할 수 있어 음성 데이터가 외부로 전송될 가능성이 있다. "비용 0원"과 "완전 로컬 처리"는 별개이며, 서비스 내 개인정보 고지에 이를 구분해 표기한다.

## 2. 사용자 규모와 실력 편차 반영 (ver.3 핵심 변경)

### 2-1. 예상 사용 규모: 동시 5명 미만, 최대 10명

- 이 규모에서는 Supabase/Vercel 무료 티어의 확장성 걱정이 사실상 없다. 인프라 설계는 "동시 접속 처리량"보다 **"운영 편의성·개인화 품질"에 집중**한다.
- 다만 무료 프로젝트의 7일 비활성 일시정지는 **동시 사용자 수가 아니라 활동 빈도**에 좌우되므로, 규모가 작아도 여전히 §4의 안내 UX가 필요하다. 오히려 사용자가 10명 이하로 서로 아는 소규모 그룹이라면, 방장/관리자가 주 1회 정도만 접속해도 프로젝트가 깨어있는 상태를 유지할 수 있다는 점은 실질적으로 유리하다.
- 사용자별 데이터 격리는 RLS로 충분하며, 소규모이므로 관리자(본인)가 Supabase 대시보드에서 질문 풀을 직접 큐레이션하기도 쉽다.

### 2-2. 실력 편차: 경어 가능/불가 + JLPT N1~N4 + 장음 발음 약점

같은 서비스를 쓰는 사용자라도 다음처럼 실력차가 크다.

- 경어(敬語)를 자연스럽게 쓰는 사람 vs 보통체 위주로만 말하는 사람
- JLPT N1 수준 vs N4 수준
- 장음(長音, ー / あ단+あ, い단+い, う단+う, え단+い, お단+う)을 짧게 발음해 STT가 다른 단어로 오인식하거나 인식률이 떨어지는 사람

이를 하드코딩된 "난이도 3단계" 같은 방식이 아니라, **① 최초 레벨 체크 → ② 질문/모드 난이도 태깅 → ③ (선택) 세션 기반 자동 조정 제안**의 3단 구조로 흡수한다.

## 3. 최초 레벨 체크(진단) 기능

첫 이용 시 1회, 이후 설정에서 재실행 가능한 짧은 진단 흐름. 전부 클라이언트 규칙 기반이며 서버/AI 호출 없음.

### Step 1 — 자가 신고 (10초)

- JLPT 수준: N1 / N2 / N3 / N4 / N5 / 모름
- 경어 사용: 자신 있음 / 애매함 / 어려움
- 장음 발음: 자신 있음 / 잘 모르겠음 / 어려움을 느낀 적 있음

### Step 2 — 짧은 진단 세션 (2~3문항, 1분 내외)

1. 자기소개 30초 자유 발화 (정중체/보통체, 답변 길이 측정용)
2. 장음 포함 단어·문장 3개 따라 말하기 (아래 §5 리스트에서 발췌)
3. 경어 문장 1개 따라 말하기 (예: "本日はお時間をいただき、誠にありがとうございます。")

### Step 3 — 규칙 기반 채점 (정규식/문자열 비교, AI 없음)

| 측정값 | 산출 방법 |
|---|---|
| 정중체 사용 비율 | 문말 어미(`です/ます` vs `だ/である`) 패턴 매칭 |
| 답변 길이/속도 | 글자 수 ÷ 발화 시간 |
| 장음 인식 위험도 | 목표 문자열과 STT 인식 결과의 장음 유무 불일치 횟수 (§5) |
| 경어 문장 재현도 | 목표 경어 문장과 STT 결과의 문자열 유사도(단순 편집 거리) |

### Step 4 — 결과 반영

- 자가 신고 + 진단 결과를 종합해 초기 `jlpt_level_estimate`, `keigo_mode`(강제/자율/보통체 허용), `chōon_risk_flag`를 계산.
- **자동 확정이 아니라 "추천"으로 제시**: "N3~N4 수준 질문 세트로 시작할까요? 직접 선택할 수도 있습니다." 사용자가 최종 선택.
- 장음 위험이 감지되면, 마이페이지에 "장음 발음 미니 연습" 카드를 노출 (§5-3).

## 4. Supabase 무료 티어 한도 대응 (유지)

- DB 500MB, Storage 1GB, 월 Auth MAU 5만 — 사용자 10명 이하 규모에서는 여유가 매우 큼.
- 7일 비활성 시 프로젝트 일시정지 가능 → 앱에 "데이터베이스가 절전 상태에서 깨어나는 중입니다" 안내 화면 기본 제공. 인위적 핑(GitHub Actions 등)으로 우회하지 않는다.
- 음성 녹음은 기본 비활성화(옵트인), IndexedDB 1차 캐싱 후 동의 시에만 업로드.
- 보관기한(TTL) 자동 삭제는 `pg_cron`이 아니라 **사용자 접속 시점에 클라이언트가 만료 레코드를 삭제하는 방식**으로 구현 (무료 티어 휴면 정책과 크론이 함께 멈추는 문제 회피).

## 5. 난이도 스펙트럼 대응 설계

### 5-1. 질문 난이도 태깅

`questions` 테이블에 다음 필드로 난이도를 명시한다.

- `jlpt_level`: N5 | N4 | N3 | N2 | N1
- `keigo_required`: true/false — 경어 필수 질문인지, 보통체로도 연습 가능한지
- `expected_duration_sec`, `answer_framework`(§기존 유지)

### 5-2. 경어 가능/불가 사용자를 위한 "경어 모드"

| 모드 | 설명 | 대상 |
|---|---|---|
| 경어 강제 모드 | 답변에 정중체가 기준 비율 미만이면 "です・ます체로 다시 말해보기" 유도 | 경어 자신 있음 |
| 경어 자율 모드 | 정중체 비율을 측정만 하고, 부드럽게 "정중체 비율 약 40%, 실제 면접에서는 권장" 정도로만 안내 | 애매함 |
| 보통체 허용 연습 모드 | 처음엔 보통체로 말해도 되지만, 세션 마지막에 "이 답변을 경어로 바꿔보기" 연습 카드 제공 | 경어 어려움 |

경어를 아예 못 쓰는 사용자도 "면접 참여 자체가 불가능"해지지 않도록, 항상 보통체로 먼저 연습하고 점진적으로 경어로 전환하는 경로를 남겨둔다.

### 5-3. 장음(長音) 인식 문제 대응

한국어에는 모음 장단 구분이 사실상 없어, 한국인 화자가 장음을 짧게 발음하면 STT가 다른 단어로 오인식하거나 인식률이 떨어지는 경우가 흔하다. 이를 "결점"이 아니라 훈련 대상으로 다룬다.

**장음 유형별 대표 예시(연습용 최소 대립쌍)**

| 장음 유형 | 예시 단어 | 장음을 짧게 발음하면 |
|---|---|---|
| あ단+あ | おばあさん(할머니) | おばさん(아주머니)으로 오인식 |
| あ단+あ | おじいさん(할아버지) | おじさん(아저씨)으로 오인식 |
| い단+い | おにいさん(형/오빠) | おにさん(비표준, 인식 오류 유발) |
| う단+う | くうき(空気, 공기) | くき(茎, 줄기)로 오인식 위험 |
| え단+い | せんせい(先生), けいご(敬語) | 짧게 발음 시 인식률 저하 |
| お단+う | がっこう(学校), ありがとう(감사) | がっこ 등 비표준 인식 위험 |

**대응 방법 (전부 클라이언트 규칙 기반, AI 없음)**

1. **장음 미니 연습 모듈**: 위 표 기반 단어/문장을 따라 말하면, STT 결과와 목표 텍스트를 비교해 "장음이 짧게 인식됐어요. ー 부분을 한 박자 더 늘려 발음해보세요" 식으로 피드백.
2. **면접 답변 중 장음 오인식 완충**: `user_custom_terms`(§7)와 동일한 방식으로, 특정 단어에서 반복적으로 장음 오인식이 발생하면 해당 단어를 개인 사전에 등록해 다음부터는 오인식된 표기를 자동으로 원래 단어 후보로 치환 제안.
3. **정확도 대신 "인식 안정성"으로 표현**: 장음 관련 피드백은 "발음이 틀렸다"가 아니라 "STT가 인식하기 어려운 발음 패턴"이라는 톤으로 제시해, 실제 일본어 실력 평가처럼 보이지 않도록 한다.

### 5-4. 적응형 난이도 자동 조정 (옵션 — 어려우면 생략 가능)

요청하신 "실력 측정 후 자동 난이도 변화"는 본격적인 적응형 학습(ML 기반 IRT 등)으로 가면 구현 난이도와 유지보수 부담이 커지므로, **단순 규칙 기반 임계값 방식**으로 축소해 제안한다. 이마저 부담되면 Phase 3 이후로 미루거나 완전히 생략해도 §3의 수동 레벨 선택만으로 서비스는 충분히 동작한다.

- 최근 3~5세션의 신호(정중체 비율, 답변 길이, 필러 횟수, 장음 오인식 빈도, 꼬리질문 통과 여부)를 단순 평균/임계값으로 계산.
- 기준 초과 시 **자동 전환이 아니라 "제안" 배너**로만 노출: "최근 답변들이 안정적이에요. N3 → N2 난이도로 올려볼까요?" / "장음 오인식이 잦아요. 장음 연습 모드를 먼저 해볼까요?"
- 실제 전환은 항상 사용자 클릭으로 확정. 자동으로 조용히 난이도를 바꾸지 않는다 (혼란 방지).
- 구현 우선순위상 Phase 3 후반 이후로 배치하며(§11), MVP·차별화 단계에서는 §3의 최초 레벨 체크 + 수동 선택만으로 충분하다.

## 7. 꼬리 질문 규칙 엔진, 자가 피드백, STT 보정 사전, 트레이닝 UX (유지 + 확장)

readme_2.md의 아래 기능을 그대로 유지하며, 레벨 체크 결과와 연동한다.

- **꼬리질문 규칙 엔진** (`follow_up_rules`: keyword/missing_keyword/answer_length/order/random) — 경어 자율/보통체 허용 모드에서는 정중체 관련 꼬리질문 트리거를 완화.
- **규칙 기반 자가 피드백**: 필러, 결론 선행, 구체성, STAR/PREP, 정중체 혼용(추정치로 표기) — `keigo_mode`에 따라 정중체 피드백 민감도를 조정.
- **STT 기술 용어·장음 보정 사전**(`user_custom_terms`): 기존 IT 용어(パイソン→Python 등)에 §5-3 장음 오인식 패턴을 같은 테이블 구조로 추가.
- **응답 지연 측정, 음성 파형 시각화, STAR 실시간 체크리스트, 답변 템플릿 코치**: 변경 없음.
- **동적 질문 출제/커스텀 질문**: `jlpt_level`, `keigo_required` 필터를 추가해, 레벨 체크 결과에 맞는 세트를 기본 추천.

## 11. 사용자 흐름 (ver.3, 업데이트)

1. **최초 가입**: 레벨 체크(자가 신고 + 짧은 진단) → 추천 난이도/경어 모드 확인 및 확정.
2. **모드 선택**: 연습/실전/약점보완/모의1차/기술/압박꼬리질문/역질문/장음 연습 중 선택.
3. **질문 제시**: 레벨·경어 모드에 맞는 질문이 TTS로 낭독.
4. **음성 답변**: STT 실시간 타이핑, 응답 지연·파형 시각화, 장음 오인식 감지.
5. **꼬리 질문(조건부)**: 규칙 매칭된 꼬리질문 제시 → 재답변.
6. **다음 질문**: 세션 진행(5~10문항).
7. **결과 저장 & 피드백**: 로그 저장 + 규칙 기반 피드백(장음/경어 신호 포함).
8. **복습**: 마이페이지에서 6축 레이더 차트, 히트맵, 오답 노트, 장음 연습 카드, (옵션) 난이도 상향 제안 배너, Markdown 다운로드.

## 13. 최종 평가

| 평가 기준 | 판단 |
|---|---|
| 0원 원칙 | 레벨 체크·장음 대응·적응형 제안 모두 클라이언트 규칙 기반으로 유지 가능 |
| 소규모 사용자(5~10명) 적합성 | 인프라 여유 충분, RLS로 데이터 격리, 관리자 큐레이션 용이 |
| 실력 편차 대응 | 자가 신고 + 짧은 진단으로 JLPT/경어 편차를 초기에 흡수, 모드로 세분화 |
| 장음 등 발음 특성 대응 | 최소 대립쌍 기반 연습 + 개인 사전 축적으로 "결점"이 아닌 훈련 대상화 |
| 적응형 난이도 | 옵션으로 축소 제안(규칙 기반 임계값 + 사용자 확인), 생략해도 서비스 완결성 유지 |
| 포트폴리오 가치 | 비용 제약 + 사용자 특성(소규모, 실력 편차, 발음 특성) 분석을 설계에 반영한 사례로 서술 가능 |

**결론**: 동시 5~10명 규모에서는 인프라 확장성보다 **개인화(레벨 체크, 경어 모드, 장음 대응)** 가 체감 품질을 좌우한다. 적응형 난이도 자동화는 규칙 기반 "제안"으로 축소해 리스크를 낮췄고, 최초 레벨 체크와 장음 최소 대립쌍 연습만으로도 요청하신 핵심 문제(경어 편차, JLPT 편차, 장음 인식 어려움)를 0원 원칙 안에서 충분히 다룰 수 있다.

## 14. 현재 범위 밖 (참고용, 채택하지 않음)

- LLM 기반 실시간 AI 첨삭/AI 생성 꼬리질문 — 유료 API 필요
- 클라우드 기반 고정밀 STT/TTS — 유료
- ML/IRT 기반 정교한 적응형 난이도 알고리즘 — §5-4의 단순 규칙 기반으로 대체, 필요성이 커지기 전까지 보류
- `pg_cron` 등 DB 크론 기반 자동 삭제 — 무료 티어 휴면 정책과 신뢰성 충돌
- Supabase/Vercel 유료 플랜 승급이 필요한 대용량 저장/트래픽 대응
- 상업 서비스/대규모 공개 운영 — 필요 시점에 별도 의사결정
